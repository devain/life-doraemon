# steelman — evolutionary scorecard

| Test | Score | Reasoning |
|---|---|---|
| **Capability transfer** | Pass | The output structure IS the lesson. After enough uses, the user runs the same five-section move in their own head when they encounter a view they disagree with. |
| **Reach extension** | Pass | Lets the user engage with views they would otherwise dismiss or strawman. Extends their epistemic reach into opposing camps. |
| **Teaching surface** | Pass | The "what you'd have to learn or accept" section explicitly names what would change the user's mind. That's the meta-lesson about how minds actually change. |
| **Long-run effect** | Pass | After 50 uses, user pre-empts demonization, asks "what's the steelman?" before reacting. The "genuine weaknesses" section keeps them from over-correcting into capitulation. |
| **Friction respect** | Pass | Preserves the *real* work — the user has to engage with the strong opponent. The gadget only removes the wasteful friction of constructing it. |

**Score: 5 hard passes.** Qualifies cleanly.

## Failure mode to refuse

If user mistakes the steelman for endorsement (yours or theirs), the gadget has misfired. The structure pushes against this — "genuine weaknesses" is mandatory, first-person voice is explicit. But the user has to honor the design.

## A note on refusal

The prompt declines views that explicitly advocate for harm against specific groups. This is not a content-moderation hedge; it's an evolutionary-test concern — steelmanning an "I should be allowed to harm group X" view does not make the user more capable, it makes them more able to launder bad ideas. The catalog is for evolution, not laundering.
